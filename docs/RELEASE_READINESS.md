## Exact production gates

1. **Backend:** use `https://makeupart-api.onrender.com/api/v1`. Confirm `/health/live` returns `{"status":"alive"}` and `/health/ready` returns `{"status":"ready"}` before releasing. Render Free may sleep while idle.
2. **Google Drive:** in Render Dashboard → `makeupart-api` → Environment, set `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, and `GOOGLE_DRIVE_REFRESH_TOKEN`. For the automated encrypted media backup, add those same three secrets separately under GitHub repository Settings → Environments → `production`; Render secrets are not automatically available to GitHub Actions. Use the Google OAuth Playground and the `drive.file` scope as described in [the runbook](PRODUCTION_RUNBOOK.md). Never paste these secret values into chat or commit them. Set `REQUIRE_DURABLE_MEDIA=true` only after a real upload, restart, restore and checksum test passes.
3. **Backups:** set a unique `BACKUP_ENCRYPTION_PASSPHRASE` (at least 24 characters) in the GitHub `production` environment and preserve it offline. Ensure the three Google Drive OAuth secrets are also present in that environment. Run the encrypted database and media backups and their restore drills. A successful encrypted database backup does not prove photo recovery; verify a non-empty media inventory and restore checksums before declaring full recovery readiness.
4. **APK signing:** configure all four of `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, and `ANDROID_KEY_ALIAS` from the same persistent keystore for update-compatible releases. When `ANDROID_KEYSTORE_BASE64` is absent, CI falls back to Flutter debug signing even if old password/alias metadata secrets remain; that APK is manual-sideload only and may not update an installed release signed by another key. Back up/export local-only photos before uninstalling an older installation.
5. **Real-device acceptance:** verify registration, login, consent reset, processing, watermark, before/after, save-to-phone, logout, and isolation between salons.

Passing CI and a recent health response do not by themselves prove durable media, database recovery, APK update compatibility or Play Store publication.
