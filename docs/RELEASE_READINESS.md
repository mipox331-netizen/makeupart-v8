## Required release gates

1. **Match the running backend to source.** Use the proposed release change that exposes Render's `RENDER_GIT_COMMIT` through `/health/ready`. The Android workflow must wait for the expected backend SHA and fail if the service never reports it ready.
2. **Prove live media durability.** Configure the three Google Drive OAuth variables in the Render `makeupart-api` service and separately configure the corresponding GitHub `production` environment secrets used by backup jobs. Upload a test image/logo through the app, confirm it exists in private Drive, restart the service, retrieve it, and compare checksums. Then require a non-empty encrypted media backup and passing isolated restore drill.
3. **Confirm database-source agreement.** Verify Render's runtime database target matches the URL used by the encrypted backup. Retain encrypted artifacts and store the passphrase in a separate safe place. The backup artifact alone does not establish that the live database was the source.
4. **Create an update-compatible Android release.** Configure `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, and `ANDROID_KEY_ALIAS` from the same persistent keystore used for the installed release. Build from the current source only after commit verification succeeds.
5. **Run a device smoke test.** Verify registration, login, trial/subscription, client selection, consent reset on photo/client changes, camera/gallery, processing, watermark/logo, before/after, gallery export, logout and fresh login on a real Android device.
6. **Enforce merge quality.** Enable `main` branch protection and require the relevant CI, dependency-security and licensing checks.
7. **Resolve commercial distribution.** Review third-party assets/models and dependency licenses; verify Play Console publication before claiming Google Play availability. iOS signing and store publication remain unverified.

A green health monitor or CI run alone is not proof of a current APK, photo durability, compatible signing, store approval, or end-to-end customer functionality.
