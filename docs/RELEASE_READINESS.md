## Required launch gates

1. **Verify the post-merge backend.** Confirm Render is deployed from the latest `main` commit and that `/health/ready` reports the exact `deployment_commit`. The release workflow should refuse to publish if it does not match.
2. **Prove real media durability.** Configure all three Google Drive OAuth variables on the active Render service and separately in the GitHub `production` environment. Upload a dedicated test portrait/logo through the app, restart the service, retrieve it and compare checksums. Then complete non-empty encrypted media backup and isolated restore drills.
3. **Verify backup target identity.** Confirm production's runtime database and backup URL reference the same Supabase project. Protect the encryption passphrase separately; never commit it or send it in chat.
4. **Publish an update-compatible APK.** Set `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, and `ANDROID_KEY_ALIAS` from the same persistent keystore as the installed release. Build only from a CI-verified source revision after backend commit verification passes.
5. **Run a real Android smoke test.** Verify registration, login, token refresh/logout, salon isolation, camera/gallery, consent reset when changing client/photo, classic makeup processing, logo/watermark, before/after display, gallery export, recent-image retention, subscription restrictions and update flow.
6. **Enforce repository merge quality.** Protect `main` and require backend/Flutter CI, dependency security and third-party license checks.
7. **Close commercial release gaps.** Confirm payment/billing behavior matches the actual admin-activation design, complete third-party asset/model license review, and verify Google Play publication before claiming availability there. Signed iOS distribution is not verified.

A passing PR CI run proves the checked source and generated debug artifact passed those steps; it does not prove the post-merge Render commit, an update-compatible release signature, Google Drive photo recovery, real-device behavior, or store approval.
