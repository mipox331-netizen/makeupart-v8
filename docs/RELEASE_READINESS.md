## Release gates still open

1. **Create a signed, update-compatible release APK.** Configure [`ANDROID_KEYSTORE_BASE64`], [`ANDROID_STORE_PASSWORD`], [`ANDROID_KEY_PASSWORD`], and [`ANDROID_KEY_ALIAS`] using the same persistent key as the installed app. Keep the signing guard enabled.
2. **Prove durable customer-media recovery.** Upload an authorized test portrait/logo through the live app, confirm private Drive objects, restart Render, retrieve both and match checksums; then complete a non-empty encrypted media backup and isolated restore drill.
3. **Verify database-source agreement.** Confirm the Render runtime and GitHub backup URLs refer to the same Supabase database without exposing credentials.
4. **Run real-device smoke tests.** Verify registration/login, trial/subscription, client selection and consent reset, camera/gallery, processing, logo/watermark, before/after, export, logout and update installation.
5. **Enforce repository rules.** Have an administrator require main CI, security audit and license inventory and restrict unreviewed direct pushes.
6. **Resolve residual security and commercial review.** Upgrade/test the vision dependencies safely, review assets/models/licenses, and verify Play Console/iOS publication before claiming store availability.

A green CI or health monitor alone is not proof of a release-signed APK, real-photo recovery, database target parity, store approval or end-to-end operation.
