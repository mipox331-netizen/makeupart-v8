## Release gates still open

1. **Create an update-compatible APK.** Configure `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, and `ANDROID_KEY_ALIAS` from the same persistent keystore used by the installed release. Build from current `main` only after CI, security, licensing and deployed-source gates pass.
2. **Prove durable media in production.** With an authorized test portrait/logo, upload through the live app, confirm both objects in the private Drive root, restart Render, retrieve the objects and match checksums. Then require a non-empty encrypted media backup and passing isolated restore drill.
3. **Verify database source agreement.** Confirm Render's runtime database URL and the GitHub production backup URL point to the same Supabase database without exposing credentials in chat or logs.
4. **Run a real-device smoke test.** Check registration, login, trial/subscription, customer selection, consent resets, camera/gallery, processing, before/after output, logo/watermark, gallery export, logout/re-login and update installation.
5. **Enforce repository checks.** Confirm branch protection/rulesets in GitHub and require the relevant CI, security and license checks.
6. **Review commercial readiness.** Review license inventory and external assets/models; verify Play Console publication before claiming Play Store availability. iOS signing and App Store publication are not verified.

A green CI or health monitor alone is not proof of a current APK, customer-photo durability, compatible signing, store approval, or complete end-to-end operation.
